# スクリプト構成と依存関係

対象: A_k(n) = #{[2n+k] の順列 p : |p(i+1) − p(i)| > n}（A179962–A179967 系列）
および a_k(n) = #{[n] の順列 p : |p(i+1) − p(i)| ≥ k}。両者は A_k(n) = a_{n+1}(2n+k)。

数学的な内容は proved_results.md を参照。本文書はコードの構成のみを扱う。

---

## 1. 依存グラフ

計算の実体は **2 つのエンジンだけ**で、他はすべてその利用者である。

```
  エンジン (依存なし)          利用者
  ─────────────────           ─────────────────────────────────
  perm_gap.rb  ◄──────────┬── aval.rb        (値の出力: 全 n)
   系統 I: 包除+frontier   │
                          └── crosscheck.rb  (2系統の独立照合)
                          ┌──
  diagdp.rb    ◄──────────┼── aval.rb        (値の出力: n >= k-2)
   系統 II: 挿入DP        ├── crosscheck.rb
                          ├── certify.rb     (漸化式の証明: Ruby)
                          ├── export_machine.rb ──► machine_kK.txt ──► diag.c
                          │                              (C/GMP: 値の出力と認証)
                          ├── alive.rb       (旧: certify に統合済)
                          └── partial.rb     (旧: 延長検証の記録)
```

C 版（diag.c）は状態機械を再実装せず、Ruby が書き出した転移表を読んで
GMP の疎行列ベクトル積だけを行う。したがって正しさの根拠は Ruby 側の検証
（全探索との一致、系統 I との照合、補題 C2）をそのまま継承する。
**値の生成に漸化式は使わない**点も Ruby 版と同じで、C_k が現れるのは
`--certify` のみ（検証の対象であって値の供給源ではない）。

`perm_gap.rb` と `diagdp.rb` は互いを一切参照しない。他のファイルは
固有の数え上げロジックを持たず、エンジンを呼ぶだけである。

## 2. 2 つのエンジン

| | 系統 I: perm_gap.rb | 系統 II: diagdp.rb |
|---|---|---|
| 原理 | 包除恒等式（定理 1.1）| 挿入過程の状態圧縮（補題 C2）|
| 符号 | 符号付き（(−1)^e で相殺）| 符号なし（すべて非負）|
| 走査 | 値の位置 1..n を掃く | 値を昇順に挿入 |
| 状態 | 直近 k−1 頂点の次数と成分分割 | (欠損量, 孤立数, 断片の端型集計) |
| 主な限界 | ギャップ k′ = n+1 で状態数が爆発 → n ≲ 7 | k で状態数が増加（k=9 で約 10⁵）|
| 呼び方 | `PermGap.series(k', 2n+k).last` | `2 * DiagDP.new(k).run(n)` |

**どちらも漸化式を使わない。** C_k やその係数はこの 2 ファイルに登場せず、
各 n について独立にゼロから数え上げる（A_k(6) の計算に A_k(5) の値は不要）。
漸化式が現れるのは certify.rb の `CK` テーブルのみで、そこでは検証の対象
であって値の生成には関与しない。

## 3. 独立性（何と何を比べると検証になるか）

**独立なペアは perm_gap.rb ↔ diagdp.rb ただ 1 つ。** コード共有ゼロ、
原理も別。これが唯一の実質的な相互検証である。

一方、次は独立ではない:

- **aval.rb ↔ diagdp.rb** — aval.rb は n ≥ k−2 で diagdp.rb を呼ぶだけ。
  比較しても同じ計算を 2 回するだけで何も検証されない。
- **certify.rb ↔ aval.rb** — 同じ diagdp.rb を共有するため、エンジンの
  誤りは両方に伝播する。
- **alive.rb / partial.rb** — 同上（かつ機能は certify.rb に統合済み）。

さらに強い基準として、公式を使わない**全探索**がある
（`PermGap.brute(k, n)`、およびハミルトンパス直接列挙）。ただし n が
小さい範囲に限られる。

### 実測: 2 系統が一致を確認できた範囲

| k | n | 最大値 |
|---|---|---|
| 3, 4, 5 | ≤ 5 | 1019616 |
| 6 | ≤ 5 | 33461568 |
| 7 | ≤ 7 | 147689145984 |
| 8 | ≤ 7 | 6690112284672 |
| 9 | 7 | 272770133833728 |

全点一致（crosscheck.rb で再現可能）。系統 I の限界を決めるのは
ギャップ n+1 であって k ではないので、**n が小さければ k がいくら大きくても
照合できる**。逆に n ≳ 8 では系統 II 単独となり、実装非依存の検証は届かない
（その領域は補題 C2 の証明が担保する）。

## 4. 値の正しさと漸化式の証明状況は別物

よくある誤解として「certify.rb で認証していない k の値は信用できないのでは」
というものがあるが、**両者は無関係**である。certify.rb が検証しているのは
「漸化式 C_k が成り立つか」であって、「A_k(n) の値が正しいか」ではない。

| 主張 | 根拠 | 対象 k |
|---|---|---|
| DP の出力 = A_k(n) の真値 | 補題 C0 + C2（証明済み）| **すべての k** |
| A_k が定数係数漸化式を満たす（次数 ≤ B(k)）| 定理 C1（証明済み）| **すべての k** |
| その漸化式が特に C_k である | 補題 10.1 + 窓検証 | k ≤ 8 のみ |

未完なのは 3 行目だけである。したがって **aval.rb / diagdp.rb / diag.c が k ≥ 9 で
出す値は、認証を走らせたかどうかと無関係に数学的に正しい**。b-file の延長、
既存項の検証、新しい k の項の計算のいずれにも、k の制限なく使える。

実際この非対称性は既に活用されている: k=9 の A_9(7) = 272770133833728 は
認証が全く走っていない状態で計算した値だが、独立な系統 I の計算と一致した
（proved_results.md §10）。値の正しさが認証と独立だからこそ、この照合が
意味を持つ。

実務上の注意:

- 証明が担保するのはアルゴリズムの正しさであり、実装が証明通りかは別問題
  （補題 C2 と diagdp.rb の照合、および §3 の独立検証がカバーする部分）。
  新しい k を計算する際は、n の小さい 1 点を crosscheck で照合しておくと安心。
- k が大きいときの実用上の制約は、正しさではなく計算時間の側にある
  （状態数は k=9 で約 10⁵）。

## 5. ファイル別の用途

| ファイル | 用途 | 実行方法 |
|---|---|---|
| **aval.rb** | A_k(n) の値を出す（通常はこれ） | `ruby aval.rb K NMAX` / `ruby aval.rb K N0 NMAX` |
| **certify.rb** | 漸化式 C_k の完全証明（認証） | `ruby certify.rb K` |
| **crosscheck.rb** | 2 系統の独立照合 | `ruby crosscheck.rb` |
| **diag.c** | C/GMP 版。値の出力・認証とも Ruby の 100〜200 倍速 | 下記 |
| perm_gap.rb | エンジン I。単体では a_k(n) を出力 | `ruby perm_gap.rb K NMAX` |
| diagdp.rb | エンジン II。単体でも A_k(n) を出力（n ≥ k のみ） | `ruby diagdp.rb K NMAX` |
| alive.rb, partial.rb | 開発過程の記録。再現には不要 | — |

補足:
- aval.rb は n ≤ k−3 を系統 I、n ≥ k−2 を系統 II で計算し、境界は
  シームレス（実測で確認済み）。単独の diagdp.rb は n < k を扱えない。
- certify.rb は生存集合を alive_K.marshal にキャッシュする。キャッシュは
  certify.rb 自身・diagdp.rb・閉包の三者の SHA-256 で検証され、不一致なら
  自動的に破棄・再計算される。
- 長い範囲（数百項以上）を出すなら、certify.rb と同じ生存刈り込みを入れると
  速い（結果は補題 9.1 により同一）。aval.rb は簡明さを優先し刈り込みなし。

## 6. C/GMP 版（diag.c）の使い方

```
ruby export_machine.rb 8              # 一度だけ: machine_k8.txt を生成
gcc-omp diag.c -o diag -lgmp          # macOS（プロジェクトのエイリアス）
cc -O3 -fopenmp diag.c -o diag -lgmp  # Linux
./diag machine_k8.txt --upto 1000     # A_8(n) を n=k-3..1000 まで出力
./diag machine_k8.txt --term 500      # 1 項だけ
./diag machine_k8.txt --certify       # C_k の認証（補題 10.1）
```

転移は目標状態別 CSR に格納してあり、OpenMP の `parallel for` が競合なしで
効く（`-fopenmp` なしでもビルド可）。実測（単スレッド）:

| 処理 | Ruby | C/GMP |
|---|---|---|
| k=8, n ≤ 1000 の値 | 約 1 時間 | **9.3 秒** |
| k=7 の認証（2798 項）| 902 秒 | **7 秒** |
| k=8 の認証（13640 項）| 12〜18 時間（推定）| **1250 秒** |

k=8 の主定理はこの実装により証明された（proved_results.md §10）。

出力の下限は n = k−3 で、それ未満は aval.rb（系統 I）を使う。

## 7. 目的別の使い分け

- **値がほしい** → 少量なら `ruby aval.rb K NMAX`、
  大量（数百項以上）なら diag.c（§6）
- **手元の値（b-file 等）を検証したい** → aval.rb の出力と突き合わせる。
  ただし本当に独立な検証をしたいなら crosscheck.rb（n ≲ 7）を使う。
- **漸化式を証明したい** → `ruby certify.rb K`。ログに
  `*** 認証成立 ***` が出れば、その k について定理として確定。
  なお値がほしいだけなら certify.rb は不要（§4 参照）。
- **エンジン自体を疑いたい** → 小さい n で `PermGap.brute(k, n)` と比較。
